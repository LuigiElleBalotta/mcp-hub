- [x] 6. Secrets: `keyring` wrapper, `${secret:...}` resolution, GUI masked editing and "move to credential store", packaging
  - `secrets.py` over `keyring` (new dependency `keyring>=25`): reference `${secret:<server>/<KEY>}`, stored under service `mcp-hub` / user `<server>/<KEY>`; `available()` is False without a usable backend (then plaintext env works exactly as before and the GUI hides the feature). Resolved ONLY when the hub spawns the process (MCP servers and services), never logged or kept; a missing secret stops the start with a message naming the REFERENCE (never a value), as an `OSError` so a lazy server's client gets a JSON-RPC error instead of a dropped connection. Logs, status, metrics and config only ever hold the reference; a service that prints its secret is still redacted.
  - CLI `secrets list|migrate|set|delete` (values never printed; `set` reads hidden input). GUI: "Sposta i segreti nel credential store" in the server dialog. Deviation from the design: no `/api/secrets/*` routes - the GUI and the hub run as the same user and reach the same store, so no secret ever travels over HTTP (better than the plan).
  - Verified for real: a set/get/resolve/delete round trip on THIS machine's Windows Credential Manager (unique test name, deleted, `cmdkey` shows nothing left), and an exe built with PyInstaller with NO extra flags reads the real store when frozen (so `release.yml` needs no change on Windows). NOT verified: the macOS Keychain backend and the macOS PyInstaller build. Renaming/removing a server does not delete its stored secrets (a reference may still point at the old name).
